# Runtime Fixture Contract

## Purpose

Freeze how standardized content packages become runtime fixtures for the mobile reader without changing app behavior or implementing the external content pipeline.

## Canonical Test Inputs

Canonical source inputs live under `fixtures/test-inputs/**`.

Source files:

- `fixtures/test-inputs/manifests/test-pack.manifest.json`
- `fixtures/test-inputs/manifests/scenario-index.json`
- `fixtures/test-inputs/publications/publications.json`
- `fixtures/test-inputs/scenarios/*/scenario.meta.json`
- `fixtures/test-inputs/scenarios/*/*.md`
- `fixtures/test-inputs/scenarios/*/expected-outcomes.json`

These files are source fixtures. They should be changed only when intentionally changing the synthetic input contract or fixing a documented validator mismatch.

Current executable source-of-truth scripts live under `scripts/content/**`:

Docs must not redefine fixture semantics that contradict these scripts.

## Built Runtime Outputs

Built runtime outputs go under `output/test-input-pack/**`.

Generated paths:

- `output/test-input-pack/runtime/*.bundle.json`
- `output/test-input-pack/reports/source-index.json`
- `output/test-input-pack/reports/build-report.json`
- `output/test-input-pack/reports/export-report.json`
- `output/test-input-pack/reports/current-scenario.json`
- `output/test-input-pack/reports/validation-report.json`

These outputs are generated state. They may be regenerated by supported npm scripts and should not be treated as hand-authored source.

## Source Vs Generated

| Path | Role | Change Policy |
| --- | --- | --- |
| `fixtures/test-inputs/**` | Canonical synthetic source inputs | Edit only for intentional contract changes or validator mismatch fixes. |
| `scripts/content/**` | Executable source-of-truth for synthetic pack validation, build, export, and selection | Do not replace in contract docs. |
| `output/test-input-pack/**` | Generated build/export reports and runtime bundles | Regenerate through scripts; do not hand-author. |
| `mobile/fixtures/runtime/scenarios/*.bundle.json` | Generated mobile scenario bundles | Regenerate through `npm.cmd run export:runtime-scenarios`. |
| `mobile/fixtures/runtime/current/**` | Generated selected scenario projection | Regenerate through `npm.cmd run select:runtime-scenario -- -ScenarioId <id>`. |

## Scenario Selection Rules

`scripts/content/select-runtime-scenario.mjs` selects an existing exported scenario bundle by `--scenario-id`. The npm script uses the PowerShell wrapper, so Windows/Codex agents should run `npm.cmd run select:runtime-scenario -- -ScenarioId <scenario_id>`.

Rules:

- A scenario id is required.
- The bundle must already exist under `mobile/fixtures/runtime/scenarios/<scenario_id>.bundle.json`.
- Selection writes the selected projection to `mobile/fixtures/runtime/current/**`.
- Selection writes `output/test-input-pack/reports/current-scenario.json`.
- Selection does not ingest raw external content and does not produce markdown.

## No Pipeline Implementation

Runtime fixture scripts may validate, build, export, and select synthetic runtime packages. They must not implement PDF parsing, web scraping, prompt generation, markdown generation, external package production, or scheduling.
